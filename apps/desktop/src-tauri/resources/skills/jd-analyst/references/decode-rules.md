# 解码规则库

> 本文件是 jd-analyst 的核心资产。所有 L2 结论必须能指回本文的某条规则。

## 1. JD 质量评估

| 信号 | 判断 |
|---|---|
| 具体且职责要求呼应（职责说搭数据体系，要求就有 SQL/数仓） | 业务方亲写，岗位真实，面试有章法 → 专业度「高」 |
| 模板腔（「负责相关工作」「完成领导交办任务」） | HR 敷衍或岗位边角料 → 专业度「低」，岗位质量分受限 |
| 有与本公司业务不匹配的词（抄竞对痕迹） | 新设岗位，团队自己没想清楚 → 解读置信度降 |
| 字数 <150 且无实质职责 | 要求用户补全 JD，不硬解 |

## 2. 权重规则（排序即权重）

- **R2.1** 职责前三条 = 入职后 80% 的日常。靠后的「参与 XX」按凑数处理。
- **R2.2** 要求前三条 = 简历硬卡点。
- **R2.3** 重复计数：同一关键词在职责+要求出现 ≥2 次 → 核心痛点，面试必问，
  面试预判必须为此出题。
- **R2.4** 位置语义：排在要求列表**末尾**的「XX 优先」是真加分项；
  **混入前三条**的「XX 优先」按硬门槛处理。
- **R2.5** 权重三档定义：
  - **硬门槛**：不满足则简历筛不过（学历/年限/执照/R2.4 命中项/要求前三条的核心技能）
  - **核心**：影响排序与谈薪，不一票否决
  - **加分**：同分候选人间的 tie-breaker

## 4. AI / 技术岗校准

- 写了具体技术栈（Agent、RAG、LangChain、微调、评测体系）→ 真在做，
  面试深挖实现细节；面试预判按技术细节出题。
- 只写「对 AI 有热情 / 拥抱变化 / AI 思维」→ 方向未定，岗位实验性，
  入职后方向可能随时变 → 机会分降、风险黄灯。
- 「大模型经验优先」出现在要求前三条（R2.4）→ 实质硬门槛；无相关经历需评估可包装性。
- 传统业务词 + AI 词混搭 → 转型期组织，政治复杂度高，考察变革推动力。

## 5. 组织语境还原

**作者推断**：HR 转写 = 规范但空泛、职责要求不呼应；业务老板亲写 = 具体、带口语情绪
（含金量最高）；模板抄写见 §1。

**招聘动因推断**：
- **替补型**：「独立负责」+ 即插即用 + 不带人不建流程 → 考核快，前三个月定生死
- **扩张型**：「从 0 到 1」+ 同部门多条相似 JD 同挂 → 机会多但乱
- **转型型**：新技能 + 老业务词混搭 → 变革阻力大，评估自身「变革推动者」体质

**业务阶段 → 人才偏好**：

| 阶段 | 偏好 | 错配信号 |
|---|---|---|
| 初创 | 全栈多面手，不计较分工 | JD 分工精细 + 初创 = 老板没想清楚 |
| 扩张 | 体系化建设、带过团队 | 只要求执行 = 是替补不是扩张 |
| 成熟 | 精细化、数据驱动 | 「从0到1」+ 成熟大厂 = 边缘实验业务 |
| 转型 | 变革推动、向上管理 | JD 无授权表述 = 光杆司令风险 |

**职级与带宽反推**：
- 带宽 >50%：公司没想清楚或愿为对的人溢价 → 谈薪空间大，锚定上沿
- 带宽 <20%：定级明确的成熟体系 → 按级谈，别乱锚
- 「向 VP/负责人直接汇报」且无带人要求 → 政治地位高但可能是光杆司令
- 汇报对象头衔远高于岗位层级 → 重点培养岗或高压接锅岗，结合口碑（L3）判断
