# 改写规则库

> 所有改写决策必须能指回本文规则，引用格式 §节号。

## 1. 事实红线（最高优先级，冲突时裁决一切）

- **不编造**：公司、项目、职责、技术栈、论文、奖项、排名、用户量、收入、准确率、
  效率提升，一律来自基础简历、素材包或用户已确认的事实。
- **包装 = 把真实经历讲清楚，不是把 0 写成 100**。允许：重组真实经历、用目标岗位
  语言重述同一事实。禁止：无中生有。
- **Ownership 责任链**：支持 < 协助 < 参与 < 负责 < 独立负责 < 主导 < Owner。
  改写不得无依据升级；「主导/设计/重构/优化/独立负责/精通」等强表述用前先查证据。
- **团队成果 ≠ 个人成果**：只能证明参与时用「支持/推动/参与实现」，不把相关性
  写成因果。
- **不抄 JD 原文**：关键词可以复用，句子不行——招聘方对 JD 原句高度敏感，且面试必露馅。
- **gaps 不进简历**：真差距靠面试准备和长期补齐，不在简历里暴露，更不由造假掩饰。
- **数字四问**（写入任何数字前）：怎么算的？基线是什么？与候选人动作什么关系？
  面试能否解释？——答不上来就降级措辞或删除。
- **无数字时的真实替代**（按优先级找）：业务/技术指标 > 效率指标 > 规模 >
  上线/验收/稳定运行 > 外部认可（获奖/开源/专利）> 决策影响 > 可验证产物
  （报告/看板/代码/数据集）。全部没有 → `[待补充：X]` 占位 + claim 登记。

## 2. Bullet 写作公式

**默认结构**：`[场景/问题] + [个人职责/判断] + [关键动作/方法] + [结果/影响]`

**成果句用 XYZ+S**：成果 X + 度量 Y + 动作 Z + 具体场景 S。
例：将需求交付周期缩短 40%（X，Y），通过引入双周迭代与需求分级机制（Z），
在电商大促保障场景下（S）。

**分岗位变体**（选最贴的一种，不混用）：
- 技术/工程：问题 → 方案 → 关键机制与取舍 → 指标/上线结果
- 数据分析：业务问题 → 指标体系/口径 → 方法 → 归因 → 推动动作 → 结果
- 产品/运营：用户/业务问题 → 分析判断 → 策略动作 → 协同推进 → 数据结果
- AI/Agent：真实场景 → 系统设计 → 个人模块 → 关键机制（workflow/检索/评测）→
  评测/上线结果

**句式纪律**：
- 一条 bullet 一个主价值，不用顿号塞 4-5 件事
- 动词开头；万能动词（负责/参与/推动 滥用）换成：设计/搭建/定位/验证/拆解/制定/复盘
- 句式必须变化：不许每条都是「通过X，实现了Y」；有的先说结果，有的直接陈述动作
- bullet 长短错落：重点条 2 行，次要条 1 行

## 3. 密度分层（按年限）

| 层级 | 证明目标 | 写法密度 |
|---|---|---|
| 0-2 年（应届/初级） | 我能上手 | 可保留执行细节，3-4 行/条；教育可前置；个人项目完整展开 |
| 2-5 年（成长期） | 我能独立做好 | 指标因果链（发现问题→分析→行动→指标变化），删执行流水，2-3 行/条 |
| 5 年+（资深） | 我能带着做大 | 只留「体系+指标+结果」，≤2 行/条；商业指标（收入/降本/ROI）；团队赋能与方法论沉淀 |

长度参考：中文一条 ≤90 字（资深 ≤60 字）；每段经历 3-5 条。

## 4. 关键词嵌入

- **证据优先**：关键词写进有证据支撑的经历句 > 技能栏罗列。技能栏只是索引，不是证明。
- **自然嵌入**：在动词短语与成果语境中出现；单条 bullet 目标关键词 ≤2 个，超了就是堆砌。
- **缩写+全称并行**（ATS 友好）：如「RAG（检索增强生成）」「SQL（Structured
  Query Language）」，保证人与机器同时可识别。
- **职位名 truthful 对齐**：JD 岗位名与实际职能一致时可对齐表述（如官方 title 是
  Product Owner 但实际全流程负责 → 写产品经理，面试时解释），但不虚高级别。
- **镜像语言体系**：优先用 JD 与公司的词汇表达同一事实（用对方的话说话），
  但句子必须重写（§1 不抄原文）。

## 5. 反模板化

- 小标题/能力标签必须来自候选人实际工作（「留存分析体系搭建」），不用通用标签（「数据分析」）。
- 各项目展开结构因内容而异，不用同一模具。
- 简历整体讲一个自洽的故事：摘要=总论点，经历=分论点，技能/教育=支撑。

## 6. 去 AI 味与语言规范

**符号红线**（中文简历正文禁用，含 Before/After 示例）：

| 禁用 | 替代 |
|---|---|
| `→` `->` 箭头 | 「到」/「提升至」/分句 |
| `——` 破折号 | 逗号或「，即」 |
| `×` 乘号 | 顿号或「与」 |
| `>` 表优先级 | 「优先于」/自然语句 |
| `""` 中文双引号强调 | 加粗 |
| 行内 `-` 分隔 | 顿号或换行（时间区间连字符除外） |
| `（）［］` 注释 | 融入正文或删除（联系方式/求职意向除外） |

- 禁空话词：认真负责/勤奋努力/吃苦耐劳/学习能力强/团队协作好——出现即删或换证据。
- 禁黑话无实体：赋能/抓手/闭环/深度参与/全面提升——后面没有具体对象、动作、结果就删。
- 中文统一中文标点（。，、；），术语可英文。
- 不用 emoji、❌✅ 做正文标记。

## 7. 转型叙事（转行/复合背景）

路径：旧经历 → 提取可迁移能力 → 用目标岗位语言重述 → 用新实践补方向证据。

- 不回避原岗位：原岗成果保留，用目标视角重述（如设计背景写「将感性设计语言拆解为
  可量化的评测维度」）。
- 时间线诚实，突出转型期的主动投入（在原岗已用新技能重构工作流）。
- 必须有新方向的实践证据（项目/作品/认证）——「想转」不是证据。

## 8. 禁写与降噪

- 不写：政治面貌、婚姻状况、身高体重、星座血型、详细住址。
- 每段经历 3-5 bullet（超 5 条必删或合并）；无第一人称代词（我/我们）。
- 与岗位无关的经历压缩为一行或移入报告 suggestions 建议删除；无关证书/兼职/校园
  事务不占篇幅。
- 非必要个人信息不主动添加（照片等按目标场景惯例，默认不加）。

## 9. 分人群分支

- **应届/经历薄**：教育前置；课程项目/竞赛/开源/自媒体按「真实投入+独立完成+明确
  方法」资产化，标注性质不包装成商业项目；教程复现项目必须写清自己的增量
  （自己加的需求/修改/部署）。
- **转行**：走 §7 路径。
- **资深**：视角从「做了什么功能」升到「构建了什么体系驱动什么业务指标」；
  带团队/方法论沉淀/跨线复制是加分维度；删执行细节。
