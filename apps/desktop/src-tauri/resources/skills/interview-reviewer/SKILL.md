# Interview Reviewer — 面试复盘

工作台闭环的最后一环：jd-analyst 预判考题 → resume-tailor 准备接招 → 实战 →
**本 skill 把「经历了」变成「学到了」**：还原面试、逐题评估、解码面试官信号、
与上游预判对账、产出可执行行动，反哺下一场。

## 常驻规则（全程适用）

1. **无人值守，一次性直出**：全程不向用户提问、不等待回复（工作台无多轮对话能力）。
   任何输入不足（转写失败、材料过短、上游缺失）都转为**降级产出 + 警示标注**，
   不允许以「请补充后继续」结束任务。
2. **原话保真**：清洗只去冗余（口头禅、重复、补标点），不改变原意；报告中引用
   面试官或候选人原话时保留原文；每条结论标注依据（时间戳或 Q 编号）。
3. **只评临场表现，不评判人**：输出聚焦「这一场说了什么、效果如何、下次怎么办」，
   不做性格、心理、智力层面的评判。
4. **上游可选不强制**：inputs 含 jd-analysis.json / tailoring-report.json 则执行对账
   （Step 4），缺失则跳过并在报告标注「独立复盘（无上游对账）」。
5. **单一职责**：不联网调研公司、不做 JD 分析、不改简历；反哺建议只写进行动清单。
6. **敏感数据留在本地**：录音与逐字稿仅在本次 run 内处理，不上传云端，产物落在
   run 目录。
7. **长材料不丢尾**：超长录音/逐字稿按结构切分分段处理再汇总；**收尾 10-15 分钟与
   反问环节是信号最密集区**，任何压缩策略不得丢弃该段。

## 输入契约

| 输入 | 必需性 | 说明 |
|---|---|---|
| 面试材料 | 必须（三选一） | ①音频文件（m4a/mp3/wav/aac/flac）②逐字稿/文字记录（md/txt，docx/pdf 提取文本）③自述文档（用户手写的面试回忆） |
| 上游产物 | 可选 | jd-analysis.json（interview_predictions）、tailoring-report.json（claims/delivery_kit） |
| 面试元信息 | 可选 | 轮次（一面/二面/HR面/终面）、面试官角色、公司岗位；未提供则从材料推断并标注 |

**降级规则**（全部一次性直出，不提问）：
- 音频存在但转写链全部失败 → 产出 schema 合法报告，`meta.transcription.status=失败`，
  warnings 说明「需先在应用外转写后以逐字稿重试」
- 材料过短（有效内容 <200 字）且无实质问答 → 降级产出，置信度「低」，
  报告首行提示补材料后重跑
- 自述文档类输入 → 正常复盘，但信号面与反问质量维度天然缺失，按 N/A 处理

**演进预留（SaaS 化）**：输入契约按「逐字稿优先、音频为便利输入」设计。未来服务端
提供转写能力时，app 侧预转写后仅传逐字稿即可，本 skill 契约不变。

## 工作流

**Step 0 输入判定**：识别材料形态（音频/逐字稿/自述）；检测上游产物与元信息；
结果写入 report.meta。

**Step 1 转写与清洗**（音频输入时）：
- 探测本机转写工具，按序尝试：`whisper-cli` / `whisper.cpp` → `whisper`（OpenAI CLI）→
  `python3 -m faster_whisper` / `mlx_whisper`（Apple Silicon）；音频格式不支持时探测
  `ffmpeg` 转码后再转写
- 转写产物落盘 `interview-transcript.md`（含说话人标注与时间戳）作为附带产物
- 口语清洗：去口头禅与重复、补标点分段，不改原意
- 说话人区分：按对话轮次与内容特征推断面试官/候选人，标注置信度（无专业
  diarization 的降级方案；自述文档天然单视角）

**Step 2 结构还原**：环节切分（自我介绍/专业问答/项目深挖/行为面/反问/收尾）→
问答清单（问题原文 + 回答摘要 + 追问链）→ 输出 `structure` 与 `qa_list`。

**Step 3 解码**：
- 面试官画像（角色/风格/关注点地图）
- 逐题评估（结构/深度/追问稳定性/时长分配 → 四级分级 + 归因分离）
- 信号识别（对照 references/signal-rules.md 逐条扫描，重点收尾段与反问环节），
  追问链聚类为疑虑地图

**Step 4 上游对账**（可选，有上游产物时）：
- interview_predictions 命中对照（问了哪些/没问哪些/超纲题）
- claims 对账（待确认表述是否被追问、防御稳不稳）
- 简历 vs 口述一致性双向检查（口述超出简历=背调风险；简历有但讲不清=高危）

**Step 5 评分与产出**：按 references/scoring-rules.md 计算六维分与总分，给通过预判
（稳/五五开/悬 + 置信度 + 依据信号）；产出行动四件套（感谢信/重答清单/下一场准备/
多轮对账）。

## 输出规范

| 产物 | 内容 |
|---|---|
| `interview-review.json` | 机读复盘（schema 见 references/output-schema.md） |
| `interview-review.md` | 人读复盘报告（打分卡先行，分析章节为依据展开） |
| `follow-up-email.md` | 感谢信草稿（默认产出，针对疑虑地图补坑 + 强化匹配点） |
| `interview-transcript.md` | 清洗后逐字稿（仅音频输入时产出，供复用与 SaaS 迁移） |

多轮次：同一岗位后续轮次的复盘自动与历史复盘产物对账（上一轮崩的题这次补上了吗），
结论写入 `actions.round_overround`。
